# Changelog

## v0.1.1

This `v0.1.1` line is still an alpha baseline, not a stability or support claim. All changes are additive to the public API; no existing public signature changed.

### Fixed

- `OpenNfsMountSessionFiles.WriteAllBytesAsync` never truncated: overwriting a 100-byte file with 10 bytes left 90 stale trailing bytes, and writing an empty payload was a no-op. The written length is now enforced with an NFSv3 `SETATTR` size change whenever the post-write size differs, so the file always ends up exactly equal to the payload.
- `WriteAllBytesAsync` required the file to exist. A missing file is now created with NFSv3 `CREATE` (UNCHECKED) in its existing parent directory; a missing parent still fails with `OpenNfsV3StatusException` (`NoEntry`), and a directory target fails with `IsDirectory`.
- `WriteAllBytesAsync` treated a legitimate NFSv3 short write (`count` smaller than requested) as a protocol error. Writes now continue from `offset + count`; only a zero-byte acknowledgement (no progress) or an over-acknowledgement is reported as `OpenNfsClientProtocolException`.
- `WriteAllBytesAsync` never issued `COMMIT`, so `UNSTABLE`/`DATA_SYNC` data was not guaranteed durable. When any `WRITE` reply reports a stability weaker than `FILE_SYNC`, the client now sends `COMMIT` and compares its verifier with the write verifier. If the verifier changed (between writes or at commit, for example after a server restart), the payload is rewritten once with `FILE_SYNC` per RFC 1813 section 3.3.21; if it keeps changing, an `OpenNfsClientIoException` explains that durability could not be confirmed.
- Mounted-session reads and writes used hard-coded 64 KiB transfers. Transfer sizes now come from `FSINFO` (`rtpref`/`wtpref`, bounded by `rtmax`/`wtmax`, capped at 4 MiB and at 32 KiB when UDP fallback is enabled), fetched once and cached per mounted session, with a 64 KiB fallback when `FSINFO` fails.
- NFSv3 `SETATTR` could not change size, mode, or ownership anywhere: the client had no `SETATTR` API, and the server rejected size and mode changes with `NFS3ERR_NOTSUPP` (and applied timestamp changes by touching the resolved host path directly, bypassing `INfsFileSystem`). Linux and other clients therefore could not truncate files (`O_TRUNC`, `truncate`, `> file`) on an OpenNFS server. See the new client API and server capability below.
- NFSv4.0 `SETATTR` only accepted ACL and owner/owner-group changes, and NFSv4.0 `OPEN` rejected every `createattrs` payload with `NFS4ERR_ATTRNOTSUPP`. Because the Linux kernel client always sends the new file's mode on `OPEN` create, Linux NFSv4.0 clients could not create files on OpenNFS (the create failed with `EIO`). Size, mode, `time_access_set`, and `time_modify_set` are now applied through the new capability for both `SETATTR` and `OPEN` create, and `supported_attrs` advertises `time_access_set`/`time_modify_set` when the capability is present so Linux clients send timestamp changes instead of an empty `SETATTR`.
- Client ONC RPC transaction ids were seeded from `Environment.TickCount`, so two clients created within the same timer tick issued identical xid sequences. Because server duplicate-request caches key on host, credential, xid, and procedure, a second client could receive a replayed (stale) reply that had been cached for the first client's identical request. Each client instance now starts from a cryptographically random xid.
- Cancelling the caller's token while an RPC was in flight surfaced as `OpenNfsClientProtocolException` ("unexpected managed client error") instead of `OperationCanceledException`. Caller cancellation now propagates unchanged on the NFSv3, MOUNT, and NFSv4 execution paths.
- Mounted sessions created by `MountAsync(...)` never sent MOUNT v3 `UMNT`, so the server's mount table (`DUMP`) grew for every session. Disposing such a session now sends a best-effort `UMNT` (bounded to five seconds, failures ignored, `Dispose`/`DisposeAsync` never throw and are idempotent). Sessions created through `CreateMountSession(...)` are unchanged.
- `LocalNfsFileSystem` on Windows could not delete or replace a file after a client cleared its write bits (the read-only attribute blocked `REMOVE` and `RENAME` over it); the attribute is now cleared first, matching POSIX directory-permission semantics.
- NFSv3 `FSINFO` now advertises `FSF3_CANSETTIME` when the host supports attribute mutation.
- The client opened a new TCP connection for every RPC. Mounted-session path resolution issues one `LOOKUP` per path component, so workloads over a few thousand small files created tens of thousands of short-lived connections, exhausting the Windows ephemeral port range (TIME_WAIT) and failing with "The TCP connection for 'MOUNT v3 MNT' ... failed". The TCP executor now keeps a per-client pool of persistent connections per endpoint (default 4, `WithMaxConnectionsPerEndpoint`). Each connection multiplexes many outstanding RPCs by xid with a single reader loop (multi-fragment record marking supported) and serialized writes; idle connections close after `WithIdleConnectionTimeout` (default 30 seconds) and on `DisconnectAsync`/`DisposeAsync`. A broken connection (server restart, reset, half-close, malformed record) fails its in-flight RPCs promptly with `OpenNfsClientIoException` and is discarded; the next RPC reconnects transparently. The response timeout still applies per RPC; cancelling one RPC never disturbs others sharing its connection (late replies are discarded), and a connection on which a call was cancelled or timed out without any reply traffic is retired and replaced. The existing retry policy is unchanged: idempotent calls are retried on I/O errors and timeouts, non-idempotent calls are not retransmitted after a disconnect. MOUNT, portmapper, and NFS program calls all use the pool.
- Mounted-session paths were split with `StringSplitOptions.TrimEntries`, so names such as `"  leading-spaces.txt"`, `"trailing-space.txt "`, or a directory `" x"` were silently created or looked up under trimmed names. Path components are now used verbatim (only `/` separates; empty components from repeated separators are dropped; `.` and `..` are still rejected) (whitespace-only names are still rejected by the client, as before).
- `LocalNfsFileSystem` on Windows silently aliased names that Windows cannot store verbatim (trailing spaces or dots are trimmed, `:` addresses an alternate data stream, `CON`/`NUL`/`COM1`... are devices). Such names are now rejected with `NFS3ERR_INVAL` on `CREATE`, `MKDIR`, `SYMLINK`, and `RENAME` targets, and `LOOKUP`/`REMOVE`/`RENAME` sources report `NFS3ERR_NOENT` instead of resolving to the aliased entry. Leading spaces, repeated internal spaces, and Unicode names round-trip unchanged; on non-Windows hosts only `/` and NUL are rejected.
- The NFSv3, NFSv4.0, NFSv4.1, and NFSv4.2 TCP hosts threw from `DisposeAsync`/`StopAsync` when client connections were still open (the cancelled per-connection tasks surfaced as `OperationCanceledException`), and an idle connection hitting the 60-second server read timeout ended with an unobserved `TimeoutException`. Shutdown now completes cleanly with open client connections, and idle connections are closed quietly.
- Stream and ranged reads failed against Linux knfsd with "NFSv3 READ failed ... closed in the middle of an RPC record" (for example `OpenReadAsync` then `Seek(2 MiB + 5)` on a 3 MiB file). The client issued an unaligned full-`rtmax` READ (offset 2 MiB + 5, count 1 MiB - 2, ending at EOF) whose reply spans one page more than `rtmax`; knfsd mis-sizes such a reply when it also needs XDR padding, logs `rpc-srv/tcp: nfsd: sent 1048706 when sending 1048704 bytes - shutting down socket`, and closes the connection mid-record (the idempotent READ was then retried with backoff, hence the 9-38 s delays). Chunked READ counts are now shortened so an unaligned read ends on a 4 KiB page boundary and every following read is page-aligned, which is the request shape the Linux client uses; `ReadAllBytesAsync`, `ReadAsync`, and `OpenReadAsync` streams all follow it.
- Pooled connections could fail an in-flight call with "The pooled RPC connection ... was retired" under heavy concurrency: a socket-readability probe used before reuse raced the reader loop and retired busy connections, and retirement could close a connection while a concurrent call was being admitted. The probe was removed (the reader loop already detects server closes) and call admission is now atomic with retirement.
- Mounted-session and grouped `CREATE`/`MKDIR` sent an all-unset `sattr3`, so servers applied their own default mode: Linux knfsd created entries with mode `000`, and a non-root AUTH_SYS user could create a directory but not write inside it (`NFS3ERR_ACCES`); root masked the problem. `CREATE` (UNCHECKED and GUARDED) and `MKDIR` now send an explicit mode, `0644` for files and `0755` for directories by default, configurable with `OpenNfsClientBuilder.WithDefaultCreateModes(uint fileMode, uint directoryMode)` (pass values with your umask applied). This covers `CreateFileAsync`, `CreateDirectoryAsync` (including `createParents`), the create-if-missing path of `WriteAllBytesAsync`/`WriteAsync`, and `Directories.CreateFileV3Async`/`CreateDirectoryV3Async`. EXCLUSIVE create is not used by the client. The OpenNFS server now applies a requested `CREATE`/`MKDIR` mode through `INfsAttributeMutation` (best effort; hosts without the capability keep their defaults), and `LocalNfsFileSystem` on Windows accepts directory modes that keep the owner write bit.
- `README.md` and `docs/release-checklist.md` now pass `--framework net10.0` to `dotnet run --project src/Test.Automated/...`; the project multi-targets, so the previous commands failed with "Specify which framework to run".

### Added: client

- `OpenNfsMountSessionFiles.ReadAsync(string path, ulong offset, int count, CancellationToken cancellationToken)` for ranged reads (fewer bytes at EOF, empty at or beyond EOF).
- `OpenNfsMountSessionFiles.OpenReadAsync(string path, CancellationToken cancellationToken)` returning a read-only, seekable `Stream` over chunked `READ` calls (`Length` is the size at open; `Dispose`/`DisposeAsync` never throw).
- `OpenNfsMountSessionFiles.WriteAsync(string path, Stream source, long? length, OpenNfsWriteStability stability, CancellationToken cancellationToken)` streaming writes with the same create, truncate, short-write, and commit semantics as `WriteAllBytesAsync` (null length copies to end of stream; an explicit length requires exactly that many bytes and throws `EndOfStreamException` otherwise; non-seekable sources are supported).
- `OpenNfsMountSessionFiles.RenameAsync(string path, string newPath, CancellationToken cancellationToken)` for files and directories.
- `OpenNfsMountSessionDirectories.ListWithAttributesAsync(string path, CancellationToken cancellationToken)` using `READDIRPLUS` with full cookie and cookie-verifier paging (restarting once on `NFS3ERR_BAD_COOKIE`), falling back to `READDIR` plus `LOOKUP` when `READDIRPLUS` is unsupported, and completing any entry that lacks attributes or a handle so every returned entry has non-null `Attributes`.
- `OpenNfsMountSessionDirectories.CreateDirectoryAsync(string path, bool createParents, CancellationToken cancellationToken)` (`mkdir -p` semantics when `createParents` is true).
- `OpenNfsMountSessionMetadata.ExistsAsync`, `SetLengthAsync`, and `SetTimesAsync`.
- `FileApis.SetAttributesV3Async`, `TrySetAttributesV3Async`, `PrepareSetAttributesV3Async`, and `ReadSetAttributesV3Result`, with the new `OpenNfsV3SetAttributes` request model (mode, uid, gid, size, access/modify time with `OpenNfsV3TimeSetMode`), an optional ctime guard, and `OpenNfsV3SetAttributesResult` (`Status`, `IsSuccess`, `Wcc`).
- `OpenNfsV3Time.ToDateTimeUtc()` and `OpenNfsV3Time.FromDateTimeUtc(DateTime)`.
- `OpenNfsClientBuilder.WithDefaultCreateModes(uint fileMode, uint directoryMode)` (defaults `0644`/`0755`), surfaced as `OpenNfsClientSettings.DefaultFileCreateMode` and `DefaultDirectoryCreateMode`.
- `OpenNfsClientBuilder.WithMaxConnectionsPerEndpoint(int)` (default 4, range 1-64) and `WithIdleConnectionTimeout(TimeSpan)` (default 30 seconds), surfaced as `OpenNfsClientSettings.MaxConnectionsPerEndpoint` and `IdleConnectionTimeout`.
- Opt-in portmapper (rpcbind, program 100000 version 2 `PMAPPROC_GETPORT` over TCP) discovery through `OpenNfsClientBuilder.WithPortmapperDiscovery(bool enabled = true)` and `WithPortmapperPort(int portmapperPort)` (default 111). When enabled, `ConnectAsync(...)` discovers the MOUNT v3 port, and the NFSv3 port when it was not set explicitly; explicit endpoints always win, an unreachable portmapper or a port-0 answer falls back to the configured endpoints, and a subsequent mount failure explains the fallback. Discovered endpoints are exposed through `OpenNfsClient.DiscoveredMountEndpoint` and `DiscoveredNfsEndpoint`, and the options through `OpenNfsClientSettings.EnablePortmapperDiscovery`, `PortmapperPort`, and `HasExplicitServerPort`. Discovery is disabled by default.

### Added: server

- `OpenNFS.Server.Abstractions.Capabilities.INfsAttributeMutation` optional host capability with `NfsSetAttributesRequest` / `NfsSetAttributesResponse`, auto-discovered on the configured `INfsFileSystem` or registered with `OpenNfsServerBuilder.UseAttributeMutation(...)`, surfaced as `NfsServerCapabilities.AttributeMutation` and `NfsCapabilityKind.AttributeMutation`. NFSv3 `SETATTR` (with ctime guard, wcc data, and `NFS3ERR_*` mapping) and NFSv4.0 `SETATTR`/`OPEN` create route through it. Hosts without the capability keep the previous standards-compliant rejection.
- `LocalNfsFileSystem` (`UseLocalFileSystem()`) and the sample provider implement the capability: size (truncate or extend), access and modification times, and mode (applied with `File.SetUnixFileMode` on Unix; on Windows only a file's owner-write bit is persisted, as the read-only attribute).
- `NfsPathInfo.Mode` plus a constructor overload that carries permission bits; NFSv3, NFSv4.0, and NFSv4.1 attribute encoders report it instead of the fixed defaults when present, and `LocalNfsFileSystem` reports real Unix modes (and `0444` for read-only files on Windows).

### Behavior changes

- `WriteAllBytesAsync` now creates missing files, truncates longer files, continues short writes, and commits unstable data (see Fixed).
- Disposing a `MountAsync(...)` session sends `UMNT`.
- `CREATE` and `MKDIR` now carry an explicit mode (`0644`/`0755` by default) instead of leaving the mode to the server.
- Chunked reads at unaligned offsets are split so they end on a 4 KiB page boundary, so a seek can add one extra, shorter READ.
- The client keeps up to four persistent TCP connections per endpoint instead of one connection per RPC; servers now see long-lived connections carrying many calls.
- Mounted-session path components are no longer trimmed; `"/docs/ readme.txt"` now addresses the name `" readme.txt"`. Backslashes are still treated as separators.
- A Windows-hosted `LocalNfsFileSystem` rejects names ending in a space or dot and names containing `<>:"|?*`, a backslash, or control characters, and reserved device names, with `NFS3ERR_INVAL`.
- `ConnectAsync(...)` performs portmapper discovery only when `WithPortmapperDiscovery()` is enabled; otherwise it still performs no network I/O.
- `LocalNfsFileSystem` now advertises the attribute-mutation capability, so `NfsServerCapabilities.AdvertisedCapabilities` includes `AttributeMutation` for `UseLocalFileSystem()` hosts.

### Tests

- New `MountSessionSuites` (31 cases): unit coverage for time conversion, SETATTR encoding/decoding and validation, xid seeding, transfer-size selection, capability discovery, and GETPORT XDR; integration coverage against an in-process `OpenNfsServerApplication` for every new API (positive and negative: missing path, missing parent, directory-as-file, negative count, cancellation before and during an RPC, seek beyond end, partial EOF reads, exact versus shorter stream lengths, non-seekable sources, zero-length payloads), 1,500-entry `READDIRPLUS` paging, 32-way concurrency on one session, `UMNT` on dispose, the README ephemeral-server snippet, fault-injected short writes, zero-progress writes, commit and verifier-change handling, restrictive and failing `FSINFO`, `READDIRPLUS` fallback and attribute completion, hosts without the capability, NFSv4.0 `SETATTR`, and portmapper discovery, precedence, unreachable, and port-0 fallback.
- `MountSessionSuites` gained 7 pooled-transport cases: 2,000+ sequential RPCs use exactly one TCP connection (counted by a proxy in front of the server), 32-way concurrency stays within the per-endpoint limit, a server restart mid-run is followed by transparent reconnection (including non-idempotent writes), killing a connection fails six in-flight `WRITE` calls with `OpenNfsClientIoException` in well under five seconds, cancelling one of three RPCs sharing a single connection leaves the others successful and discards the late reply, the response timeout bounds calls on a black-holed connection which is then replaced, and idle connections close after the idle timeout and on `DisconnectAsync`. The shared scenario matrix gained a special-character-names step (leading spaces, trailing spaces, repeated internal spaces, trailing dots, a leading-space directory, Unicode including an astral-plane emoji) round-tripped through `WriteAllBytesAsync`, `ReadAllBytesAsync`, `ExistsAsync`, `ListWithAttributesAsync`, `ListAsync`, and `RenameAsync`, with verbatim host names asserted for the in-process server and `NFS3ERR_INVAL` (never aliasing) for Windows-unsafe names.
- The NFSv4.0 loopback test harness now serves multiple calls per connection and counts requests instead of connections.
- The scenario matrix gained the exact knfsd-failing stream sequence (write 3 MiB + 3 bytes, `OpenReadAsync`, seek to 2 MiB + 5 and read 100000 bytes, rewind and read 1000, read the last 10 bytes, read at and beyond EOF) plus `ReadAsync` at EOF, beyond EOF, and with zero count, run against OpenNFS, knfsd, and NFS-Ganesha; `ReadCountsAreAlignedToPages` and `UnalignedReadsStayWithinTransferPages` pin the READ request shape.
- New create-mode cases: `CreateAndMkdirSendDefaultModes` (in-process; wire-level mode assertions and a honored custom mode) and `CreateModesAndOwnershipAgainstLinuxKnfsd`/`Ganesha`/`Unfs3` (a non-root uid creates `identity/sub` with `createParents`, creates, overwrites, streams, lists, and deletes files and nested directories inside it; `stat` inside the container reports `755`/`644` owned by that uid; another uid is denied; configured `0600`/`0700` modes are honored). The unfs3 peer now also runs with a tmpfs export so Unix modes are real.
- New `InteropMountSessionSuites` (5 cases): the same mounted-session scenario matrix (including 1,500-entry listing and 32-way concurrency) against Docker Linux knfsd and NFS-Ganesha (NFSv3) peers, portmapper discovery of knfsd's `rpc.mountd` through a real rpcbind, and Linux kernel client NFSv3 and NFSv4.0 `O_TRUNC`, `truncate`, `: >`, `touch -d`, and `chmod` against `Sample.OpenNfsServer`. Containers are always removed, including on startup failure.
- The NFS-Ganesha interop image gained an NFSv3-enabled configuration (`ganesha-v3.conf`, selected with `GANESHA_CONFIG`), and the knfsd image accepts `MOUNTD_PORT`.
- Docker test harnesses now remove containers through a verifying, retrying cleanup (`DockerContainerCleanup`). Previously a single `docker rm --force` often killed privileged knfsd containers without removing them while the kernel NFS server was still tearing down, leaving exited containers behind after every run.

### Verified

- Concurrency: one `OpenNfsClient` / `OpenNfsMountSession` is safe for concurrent use. Every RPC opens its own TCP connection and validates the reply xid, so replies cannot be cross-delivered; 32-way concurrent writes, reads, ranged reads, lookups, GETATTRs, and listings on one session pass against OpenNFS, Linux knfsd, and NFS-Ganesha. No internal serialization was added.
- `ListAsync` paging and cookie-verifier handling were audited and are correct; `ListWithAttributesAsync` additionally restarts once on `NFS3ERR_BAD_COOKIE`.

### Known limitations

- The default `IntrinsicHandleProvider` embeds the source path in the filehandle, which exceeds the 64-byte NFSv3 limit for typical paths (MOUNT fails with `MNT3ERR_SERVERFAULT`); keep pairing `UseLocalFileSystem()` with `PersistentMappingHandleProvider` for NFSv3, as documented.
- NFSv4.1/4.2 `SETATTR` is not routed through `INfsAttributeMutation` yet; NFSv4.0 `SETATTR` does not validate the supplied stateid, and an empty NFSv4.0 `SETATTR` mask still returns `NFS4ERR_INVAL`.
- `LocalNfsFileSystem` does not change numeric owner or group (`NFS3ERR_NOTSUPP` unless the value matches the reported owner `0`), and on Windows only a file's owner-write bit is persisted.
- There is no client-side LOOKUP handle cache: path resolution still issues one `LOOKUP` per component per operation (now over pooled connections). A cache was not added because its invalidation cannot be made correct against other clients renaming or replacing directories.
- After a connection drops, a non-idempotent call that was in flight fails with `OpenNfsClientIoException` rather than being retransmitted (the server may already have executed it); callers decide whether to retry.
- The OpenNFS server hosts process calls sequentially per connection, so concurrency against an OpenNFS server is bounded by `MaxConnectionsPerEndpoint`.

## v0.1.0

This `v0.1.0` line is still an alpha baseline, not a stability or support claim.

- Established the repository baseline, solution structure, and central .NET build configuration.
- Added the initial public configuration surfaces for `OpenNFS.Server` and `OpenNFS.Client`.
- Added the initial `OpenNFS.XdrGen` manifest-validation workflow and Touchstone-based test harness.
