# Changelog

## Unreleased

- Established the repository baseline, solution structure, and central .NET build configuration.
- Added the initial public configuration surfaces for `OpenNFS.Server` and `OpenNFS.Client`.
- Added the initial `OpenNFS.XdrGen` manifest-validation workflow and Touchstone-based test harness.
- Added `OpenNfsServerApplication` and `OpenNfsServerBuilder.BuildApplication()` as the primary public runnable server path, switched `Sample.OpenNfsServer` onto that wrapper, and added direct plus clean-package-consumer runtime validation over real NFSv3 and NFSv4.0 flows.
- Updated the public packages so both `OpenNFS.Server` and `OpenNFS.Client` produce `.nupkg` plus `.snupkg` artifacts with XML docs, README, and license content, and so `OpenNFS.Server` now bundles the internal protocol/runtime assemblies required by `BuildApplication()`.
- Added reusable temp-export, principal, packet-capture, README-snippet, and fault-injection test infrastructure; new forced-disconnect and duplicate-on-wire recovery suites; and clean packaged-consumer compilation coverage for the canonical README client and server snippets.
- Extended the recovery and fault-injection slice with dropped-reply reconnect replay coverage for the NFSv3 duplicate-request cache, stable requester-identity correlation across reconnect, explicit negative changed-requester replay coverage, NFSv4.0 lease-expiry re-registration recovery coverage, and executor-driven expired lock cleanup so host lock state is released when v4.0 client state ages out.
- Closed the Phase 9.2 identity-mapping acceptance gap with real Linux-kernel-mounted NFSv4.0 `stat` / `chown` coverage against `Sample.OpenNfsServer`, including a negative case for missing local principals, and widened the current NFSv4.0 attribute surface to satisfy Linux kernel mount expectations on that path.
- Added an OpenCIFS-aligned local server export-introspection path through `OpenNfsServerBuilder.GetExportsAsync(...)` and `OpenNfsServerApplication.GetExportsAsync(...)`, and pinned that shape in `ServerSurfaceSuites`.
- Bound the remaining legal NFSv4.0 core operations explicitly, including `PUTPUBFH`, `VERIFY`, `NVERIFY`, and capability-gated `OPENATTR`, `DELEGPURGE`, and `RELEASE_LOCKOWNER`, and added raw client/server Touchstone coverage for the advanced COMPOUND surface.
- Replaced the sample's bare filesystem-only path with a real durable sample provider that persists ACL state, exposes configurable owner and owner-group mapping, exercises the current locking and delegation seams over a disk-backed export, and added positive plus negative sample-artifact validation for mounted-session semantics and direct NFSv4.0 capability flows.
- Added release-readiness automation with a formal `docs/release-checklist.md`, source-level skipped-test enforcement, a shared `ReleaseReadinessSuites` validator suite, hosted and self-hosted workflow scaffolding, and first plan-mode harness entry points for privileged interop, `pjdfstest`, Connectathon, and `pynfs`.
- Added a repository-honesty gate (`Assert-RepositoryHonesty.ps1`) plus positive and negative shared-suite coverage, and wired that validation into release-plan generation and CI workflow execution.
- Extended the release-readiness package-consumer matrix so a packaged `OpenNFS.Server` is mounted and used by a Linux kernel client, and a packaged `OpenNFS.Client` executes positive and negative flows against `Sample.OpenNfsServer`, `knfsd`, and `nfs-ganesha`.
- Hardened the Linux sample-mount and `knfsd` NFSv4.0 readiness harnesses with reread retry logic and a clean container-start retry so the adapter runners stay stable under slower interop startup conditions.
- Added builder-level `AUTH_SYS` identity configuration through `OpenNfsAuthSysCredentials` and `OpenNfsClientBuilder.WithAuthSysCredentials(...)`, plus shared mount/bootstrap coverage proving the configured machine, uid, gid, and supplementary gids are carried onto real MOUNT traffic.
- Added `OpenNFS.TestClient` and `OpenNFS.TestServer` as menu-driven console tools for manually exercising the current public client and server surfaces, including export enumeration, mounted-session browse and mutation flows, temporary disk-backed server hosting, and direct remote-client connection paths.
- Reworked the test-runner split so `Test.Automated` remains the only exhaustive heavy matrix runner, while `Test.Xunit` and `Test.Nunit` now execute a fast unit-tagged adapter-smoke subset instead of rerunning Docker, packaged-consumer, and peer-matrix coverage a second and third time.
- Added a bounded OpenCIFS-aligned client parity slice with `OpenNfsClientResult` / `OpenNfsClientResult<T>`, `OpenNfsErrorCategory`, typed client exceptions for state, protocol, transport, MOUNT v3, and NFSv3 path failures, plus `TryConnectAsync(...)`, `TryDisconnectAsync(...)`, `TryMountAsync(...)`, and export bootstrap `Try...Async` companions on the primary client path.
- Added the first real identity-plumbing slice with public server-side identity set/get contracts, `OpenNfsClient.Identity`, pluggable `IOpenNfsClientIdentityPolicy` mapping including `OpenNfsLinuxStyleIdentityPolicy`, NFSv4.0 owner/group `SETATTR` support, dedicated `IdMapSuites`, owner/group update coverage on the direct NFSv4.0 peer path, and sample-artifact identity persistence across restart.
- Added the bounded OpenCIFS-aligned managed server lifecycle slice with `OpenNfsServerResult`, `OpenNfsServerException`, `OpenNfsServerStateException`, and `OpenNfsServerApplication.TryRunAsync(...)`, `TryStartAsync(...)`, and `TryStopAsync(...)`, plus shared surface coverage for duplicate starts, bind conflicts, and disposed-application misuse.
- Added `--suite <SuiteId>` filtering to `Test.Automated` so targeted validation can run only the touched Touchstone suites instead of the entire heavy matrix.
